## 2. Decisions

Asked for by the human:

1. **Local is a first-class environment.** `wrangler dev` at `http://localhost:8787` runs the same code as staging and production, with its own data ([cloud.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/cloud.md) section 9). All three behave identically; the only differences are their data and the **LOCAL** / **STAGING** strip ([environments.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/environments.md) section 3.2). That is the cloud's to keep, not the agent's.
2. **The agent is the only thing linked between environments.** Recorded as decided in [environments.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/environments.md) section 2.
3. **A tray app** for Windows, macOS and Linux, with no website of its own (but for decision 8's settings page). The icon shows the link state; the menu has **Link to** local / staging / production (one connection and one token per environment, as environments.md section 2 already decides), **Open on retaskable.com**, **Pause** and **Quit**.
4. **Orchestration doesn't change**: plain `claude -p` / `cursor-agent -p`, `git` and the code host's CLI. The agent's HTTP API stays bound to `127.0.0.1` only (but for decision 8's network access, which the person at the computer turns on), takes no command, and its cloud link stays outbound only.
5. **Everything else is on retaskable.com.** What the site does is the cloud's and the app's, not this spec's ([cloud.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/cloud.md) section 6 lists the commands the agent takes).
6. **What's lost** is said plainly (section 7): there's no UI beyond the tray menu without a reachable retaskable.com.
7. **(2026-10-02) A development build links to every environment at once; a release build links to the one environment it was built for.** Whoever works on Retaskable runs one agent on their machine and needs it connected to their local server, staging and production together, so a **development build** (the agent run from a checkout of the repo) offers **Link to** Production, Staging, Local and Custom, several linked at once (section 4.6, built). A **release build** (an installed agent, section 8) links to **the one environment it was built for**: Production for the build everyone installs, Staging for the people testing Retaskable (changed 2026-10-18, [installers.md](../installers.md) section 2). Its **Link to** has the one entry, **Custom** and `cloud.url` / `RETASKABLE_CLOUD_URL` are ignored, and `npm run link -- <environment>` refuses any other environment. What makes a build a release build is fixed when it is packaged, never a setting a person can flip at run time; until installers exist (section 8) every agent is a development build. (agent-bundle slice 2, [installers.md](../installers.md) section 3.8): a release build's `cloudUrl` and `cloudUrls` are its `build.json` environment's alone, and `retaskable link` refuses another.
8. **(2026-10-22) A deliberate exception to "no website of its own": a tiny local settings page.** The settings only a computer changes (its port, local model, how often it checks, tags, Cursor's models) were spread over the config file and requests someone allowed. The human asked "could we use a tiny webserver?", and then "that way you could navigate to your local ip with the agent running and change the settings remotely from within the network". So the agent's port also serves `/settings`, a plain page with no app code, which the tray's **Settings…** opens ([agent-settings.md](../agent-settings.md) section 4). It shows and changes those settings only: never a command, never the project's settings, never anything the website changes. It's on `127.0.0.1` with a one-time token from the tray; on the local network only when the person at the computer turns network access on and sets a password. Everything else stays on retaskable.com.

**[Proposal]** And to make them work:

- **The tray is a small helper, not a web view** (section 4).
- **What a computer runs is approved by its owner on the site, never by a command.** Since 2026-10-22 a linked computer takes its project's commands at once, and what keeps "no remote code execution" true is that the commands it runs change only by an owner and run only once the computer's owner approves them on the site ([cloud.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/cloud.md) sections 6.1 and 6.4). The agent checks each command itself before it runs ([cloud.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/cloud.md) section 6.2).
