## 4. The tray agent

### 4.1 The icon

One icon, its state the combination of the environments it's linked to, worst first:

| State | When | Icon |
|---|---|---|
| **Not linked** | no environment has a token | the tanooki on grey |
| **Waiting** | a link is waiting for its code to be approved | RT with an amber dot |
| **Offline** | a linked environment can't be reached, or answered `invalid_grant` | RT with a red dot |
| **Connected** | every linked environment is connected | RT with a green dot |

**[Proposal]** The tooltip names each linked environment's state ("Production: connected · Local: offline"), and **Paused** is added to it while the orchestrator is paused.

### 4.2 The menu

```
Retaskable · running (2 sessions)        (status line, disabled)
───────────────
Link to ▸   Production   ● Connected       (Forget)
            Staging      Not linked        (Link)
            Local        ○ Waiting: WXYZ-2345 (Copy code / Open link page)
Open on retaskable.com ▸  Production / Local     (one entry per linked environment)
───────────────
Pause  /  Resume
Settings…                                (this computer's own settings, decision 8)
✓ Start at login                         (a release build only; Start with Windows on Windows)
Open the log                             (a release build only)
Quit
```

- **Link to** (a development build's, decision 7; a release build shows only its own environment) is a submenu: each environment with its state; **Link** runs the device flow ([cloud.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/cloud.md) section 4.2) against that environment's URL and opens `/link?code=…` in the default browser; a linked one offers **Forget**, which deletes that URL's token and closes its connection. One connection and one token per environment ([environments.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/environments.md) section 2). **[Proposal]** A custom `cloud.url` is a fourth entry, **Custom**, as environments.md section 3.4 says.
- **Open on retaskable.com** (**Open Retaskable** in a release build, above **Link to ▸**: the waiting code's page, a new code when there's none, `/start` until this computer has a project, `/` after, [setup-in-app.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/setup-in-app.md) section 3.0; in the desktop app it opens the window instead, section 4.5) opens the linked environment's site in the default browser. With one environment linked it's a plain entry; with none it's greyed out, "Link first". Which project the site opens on is the site's to decide.
- **The shared backlog** has no entry of its own ([installers.md](../installers.md) section 4): the agent links to the store by itself, and while it isn't linked the store's approval waits for the person at the machine (**Approve the shared backlog** with **Open the link page**, or **Unlinked on <host>: link again?** with **Link again**). It changes nothing in the icon, which is retaskable.com's environments'. The agent fails closed while it can't reach the store.
- **Pause** / **Resume** is the orchestrator's global pause, the same call as the `pause` and `resume` commands.
- **Settings…** opens the computer's own settings page in the default browser, at `http://127.0.0.1:<port>/settings#<token>`, a new one-time token each time (decision 8, [agent-settings.md](../agent-settings.md) section 4). The terminal menu has it too, and says the link. Built (computer-settings-page).
- **Start at login** (a release build only, [installers.md](../installers.md) section 3.14), "Start with Windows" on Windows: a tick, on while the OS starts this build when the user signs in; a click turns it the other way. Built (staging-builds slice 2).
- **Open the log** (a release build only, [installers.md](../installers.md) section 3.2) opens its log file in the default app for it, since it has no terminal. Built (agent-bundle slice 2).
- **Quit** stops the agent. **[Proposal]** While sessions run it asks first: **Quit when idle** (the restart's path, [agent.md](../agent.md) section 8 `/api/restart`, exiting instead of restarting, and waiting for everything running to finish, which a restart no longer does) or **Quit now** (stops the running sessions; their items go back as on any crash).
- **Waiting for you** appears at the top while the shared backlog's approval waits for the person at the machine ([installers.md](../installers.md) section 4), and a native notification says the same. Nothing the website sends waits here: the commands it sends run at once with the agent's own checks.

### 4.3 What stays the same

The orchestrator, lanes, sessions, the config file, the cloud connector (one per environment, environments.md section 3.4), the command checks ([cloud.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/cloud.md) section 6.2) and the `remote` policy. The HTTP API is gone but for `GET /api/health`, still on `127.0.0.1` only (since 2026-10-22 beside the computer's own settings page, decision 8, on the network only once turned on with a password); it never takes a command. The tray helper speaks JSON over stdin and stdout (section 4.6), and `npm run link` and the console call the orchestrator in process. Nothing new listens anywhere else.

### 4.4 Without a tray

**[Proposal]** `npm start -- --no-tray` runs headless (servers, CI, a Linux desktop with no tray, such as GNOME without its AppIndicator extension), printing the link state to the console; linking there is `npm run link -- <environment>` (environments.md section 3.4), unchanged. With a terminal on stdin and stdout, the tray's menu is drawn in that terminal instead (section 4.7).

### 4.5 The wrapper: options

| Option | Size | What it adds | Verdict |
|---|---|---|---|
| **Electron** | ~100 MB+, a whole Chromium | a second runtime and its own packaging and updates, for a window we no longer have | No: it's built for windows, and there aren't any. Changed 2026-10-20: yes, for the desktop app, whose window is the web app (below) |
| **Tauri** | ~5–10 MB plus the system web view | a Rust toolchain and a Node sidecar for the agent: two languages to build and sign on three OSes | No: smaller, but two toolchains for one menu |
| **A minimal native tray helper** | ~3–5 MB per OS, prebuilt | a tiny helper binary the agent spawns, speaking JSON over stdin / stdout (icon, tooltip, menu items, clicks), e.g. the `systray2` package's prebuilt helpers | **[Proposal] Picked** |

The helper is the simplest: the agent stays one process run the way it is today, the helper only draws the icon and menu and reports clicks, and if it can't start (no tray on that desktop) the agent carries on headless (section 4.4). Linux needs AppIndicator support (`libayatana-appindicator`), said in the README. Installers, signing and start-at-login are left for later (section 8).

**[Decided]** (2026-10-20) **The desktop app's window is the web app.** For people who never use a terminal the agent ships inside an Electron app ([desktop-app.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/desktop-app.md)), on macOS first, then Windows: the agent runs in Electron's Node as the same code, Electron's `Tray` draws this section's menu from the same `trayMenu()` model in place of the helper, and **Open on retaskable.com** becomes **Open Retaskable**, a window showing the web app on the environment it was built for (its live site, not a copy, and not a website of the agent's own: decision 3 holds). Closing the window leaves the icon and the agent running. A checkout and Linux keep the helper.

### 4.6 Details

- **The helper** is `systray2`'s prebuilt one (systray-portable, a dependency of `agent/`), spawned by `agent/src/trayHelper.ts` with its own JSON-lines client rather than the package's JavaScript: `{"type":"ready"}` from the helper, then the whole menu as the first line, then `update-item` (one item, by its id) and `update-menu` (icon and tooltip only). The helper builds its menu once and can't add or remove items, so `agent/src/tray.ts` gives the menu the same items in every state (each hidden while it says nothing) and only their text, enabled and hidden change; every field is always sent, since the helper reads a missing one as false. Only what changed is sent, parents before children. On Windows the helper deletes a hidden item and inserts it again when shown, without its submenu, so an item that can be hidden never has one: the backlog's approval and **Open on retaskable.com**'s many are `inline` in the model, and the helper draws their items as indented lines under them, hidden with them (`drawn` in `trayHelper.ts`). The terminal menu still shows them as a submenu.
- **The icon** (`agent/src/trayIcons.ts`) is the tanooki logo drawn with sharp at 32 px: on grey for **Not linked**, on its Sun tile with an amber, red or green dot for **Waiting**, **Offline** and **Connected**; a PNG on macOS and Linux, an ICO holding that PNG on Windows. A release build carries no sharp: its icons are drawn when it's built and read from the `icons/` beside it ([installers.md](../installers.md) section 3.9). The tooltip is section 4.1's ("Retaskable · Production: connected · Local: offline", the environments not linked left out, Production's state when none is), with "Paused" while every project is and "1 waiting for you" while the shared backlog's approval waits.
- **The menu**: the status line ("Retaskable · running (2 sessions)", "· paused", "· idle", "· no project yet", "· quitting when idle", and "· restarting for new code" for the moment a restart to load merged agent code takes (finishing a merge first, at most; [agent.md](../agent.md) section 4.2), so a menu from the old code says it is one; then "· restarted at 14:05" after it for 10 minutes once it's back); under it, greyed out, the computer's name and tags ("jcnash-pc4 · tags: windows, gpu, display", [computer-tags.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/computer-tags.md) section 3.1); **Waiting for you** with the shared backlog's approval under it while this machine isn't linked to the store ([installers.md](../installers.md) section 4); **Link to ▸** with Production, Staging, Local and, when `cloud.url` is none of them, Custom (4 slots, the Custom one hidden while there's none), each with its state ("Local (localhost:8787): waiting: WXYZ-2345") and **Link to Local** (the device flow against that URL, opening its `/link?code=…` in the default browser; one link at a time per cloud, several clouds at once), **Open the link page to approve WXYZ-2345** while waiting, **Forget Local** once linked (`Connector.forget` on that cloud's connector: deletes its refresh token, closes its connections, drops a token refresh under way without storing what it gets, and waits unlinked; the others stay connected), or **Link to Production again** for a cloud that answered `invalid_grant` (its token deleted, it reads **Offline**, "unlinked on the website", until it's linked again or forgotten); **Open on retaskable.com**: with one environment linked, a plain **Open on staging.retaskable.com** (its `/`), with none greyed out "link first", and with several a submenu of them ("Production (retaskable.com)", "Local (localhost:8787)"), the helper being unable to turn the one into the other, so both are there and one is hidden; **Pause this computer** / **Resume this computer** (every project, on this computer only, never the shared backlog's pause; Resume once all are paused); **Quit**, which is **Quit now** with **Quit when idle** beside it while sessions run (the restart's path, exiting with 0 instead of 75, once nothing is running). Every way out (Quit, Ctrl+C, SIGTERM, restart) tells the helper to exit and closes its input first. The default browser is opened without a shell (`rundll32 url.dll,FileProtocolHandler`, `open`, `xdg-open`), and only for `http(s)` URLs.
- **Refreshed** every 2 seconds and at once on each event the agent announces. A click runs the action of the item as it was last shown; a greyed-out or hidden item does nothing.
- **Without a tray**: `--no-tray` (`npm start -- --no-tray`; `scripts/supervise.mjs` passes its arguments on) or `RETASKABLE_NO_TRAY=1`, a Linux with no `DISPLAY` or `WAYLAND_DISPLAY`, a helper that doesn't start or isn't ready within 10 seconds, or one that stops later: the agent says so in the console and runs headless. With no tray from the start (the first three) and a terminal on stdin and stdout, the menu is the terminal menu instead (section 4.7); a helper that fails or stops leaves the plain console, as before.
- **A connector per environment** (slice 2, environments.md section 3.4): `agent/src/clouds.ts`, one `Connector` per cloud, the agent's own cloud (`cloud.url`, production by default) keeping the organisations and release notes; `npm run link -- staging` in the terminal.
- **A native notification** for the shared backlog's approval (slice 3): the helper draws none, so `agent/src/notify.ts` runs the OS's own tool, without a shell, when it waits and the tray is up: a Windows PowerShell toast under PowerShell's app id (its script fixed and sent `-EncodedCommand`, the text read from the environment), `osascript`'s `display notification` (the text as the script's arguments) on macOS, `notify-send` on Linux. "Retaskable: waiting for you", then the sentence. Best effort: with no such tool (a Linux without `notify-send`) nothing shows and the menu still has it. Clicking it doesn't open the menu (nothing can, from outside the helper); it only dismisses it. Headless, the console line is all. (Allow and Deny buttons on the Windows toast went with the website's requests, retired 2026-10-22.)
- **Tested** in `agent/src/tray.test.ts` (the states, the menu's fixed shape with one to four clouds, each cloud's link items, Open on with one or several linked, `invalid_grant`'s Offline, quit items, the helper's protocol against a fake helper, the icons, the clicks, `openUrl`, the notification only while the tray is up and `notify`'s commands), `clouds.test.ts` (two clouds at once), `link.test.ts` (two links at once) and `connector.test.ts` (`connected()` and `forget()`).

### 4.7 The terminal menu

The tray's menu for a machine with no desktop: a headless Linux box, a session over ssh, later a Docker container (2026-10-16, the human: "the text UI would just be to replace the tray menu"). It is the tray's menu and nothing more: the same `trayMenu()` model (section 4.6), drawn in the terminal, and a chosen item runs the same action through the same `TrayAgent` code as a click in the tray (its action as last shown; a greyed-out or hidden item does nothing). Nothing the tray menu doesn't have is here, and nothing typed runs anything.

- **When**: `--tui` (`npm start -- --tui`) or `RETASKABLE_TUI=1` draws it instead of the tray; with neither, it's drawn whenever the agent would run without a tray from the start (`--no-tray`, `RETASKABLE_NO_TRAY`, a Linux with no `DISPLAY` or `WAYLAND_DISPLAY`, an OS with no helper). Only when both stdin and stdout are a terminal: with the output going to a file (the agent started with `Start-Process -RedirectStandardOutput`, a service) it is never drawn and the agent runs as before. `--no-tui` or `RETASKABLE_TUI=0` keeps the plain console. The console takes no typed commands.
- **What it shows**: full screen in the terminal's alternate screen, plain ANSI (no dependency): the status line as a header, the tooltip's line under it (each environment's state, "N waiting for you"), then the menu: separators as rules, hidden items left out, greyed-out ones dimmed, a submenu marked `▸`, **Waiting for you** and the shared backlog's approval highlighted; an open submenu replaces the list, headed by its path (`‹ Link to`). Under the menu, the last lines of the console that fit: while the menu is up, `console.log` and friends go to that pane instead of the screen, and once it closes (quit, restart, crash) everything they said meanwhile is printed on the normal screen, so the scrollback has it (the last 2000 lines). A narrow terminal cuts each line with `…`; a short one scrolls the menu to keep the cursor in sight. It's drawn again when the menu changes (the same refresh as the tray's: every 2 seconds and on each event the agent announces) and when the terminal is resized.
- **Keys**: ↑ ↓ (or `k` `j`) move over what can be chosen, Home and End; Enter or Space opens a submenu or chooses an item; → (or `l`) opens a submenu; ← , Esc (or `h`, Backspace) goes back. `q` doesn't stop the agent: it says to choose **Quit** or **Quit when idle**, or press Ctrl+C. Ctrl+C stops the agent as SIGINT does (Quit now), after putting the terminal back. Nothing asks to confirm, as the tray doesn't.
- **The shared backlog waiting** shows as a highlighted line under the header ("! Retaskable: approve the shared backlog: …", until the next key) with a terminal bell, instead of the desktop notification (it goes in the log pane too).
- **Opening a page** (Open on …, the link page, Link to …) also prints "Open <url>" in the log, for a machine with no browser; the browser is still tried.
- **The terminal is always put back** (cursor shown, raw mode off, the normal screen): on Quit and Quit when idle, on Ctrl+C and SIGTERM, on a restart to load new code (exit code 75: the supervisor's next agent draws it again), and on a crash, before the error is printed (`uncaughtExceptionMonitor`, and the `exit` event).
- `agent/src/terminalMenu.ts`. `renderScreen` (menu, cursor, size, log lines → screen lines) and `handleKey` (menu, cursor, key → cursor, the key of the item to run, or stop) are pure; `TerminalMenu` is a `TrayView` (`agent/src/trayAgent.ts`: what draws the menu and reports a choice, the tray helper's other implementation), wired in `agent/src/index.ts` by `useTerminalMenu`. Tested in `agent/src/terminalMenu.test.ts`: each kind of item, hidden and greyed out, submenus, cutting to width, scrolling, the backlog highlight, the keys, the cursor staying put as the menu changes, a choice running the tray's own handler (Pause, Quit), the console captured and printed again, and the terminal put back on stop, exit, a crash and Ctrl+C, once.
