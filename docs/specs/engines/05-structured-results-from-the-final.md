## 5. Structured results from the final message

Built (`jsonResult.ts`, `check.ts`, the reader's `result` line, and `spawnWithRetries`). Claude Code fills `structured_output` from `--json-schema`. Cursor can't, so:

1. **Asking.** The prompt (`prompt(spec)`) ends with the result instructions: the role's schema (the same object from `agent/src/schemas.ts`), and "When you've finished, end your final message with exactly one fenced ```json block holding your result, matching this schema. Nothing after it."
2. **Extracting**, in plain code: from the `result` event's text (else the last assistant message), the last fenced block tagged `json`; failing that, the last top-level `{…}` that parses as JSON.
3. **Checking** it against the same schema, with a small checker in `agent/src/engines/check.ts` for the keywords the result schemas use (`type`, `properties`, `required`, `enum`, `items`, `additionalProperties`), no new dependency; its errors are short lines like "`status`: must be one of pr_opened, needs_clarification, failed".
4. **Asking again.** When there's no block or it fails the check, the runner resumes the same chat with "Your last message had no valid result: <errors>. Reply with only the ```json block." Up to 2 times; then the session's result is `ok: false` with the last errors as `error`, which the step handles as it handles a Claude session with "No structured output returned" today.

- A good result is `SessionResult.structured`, so the steps, the orchestrator and the result schemas don't change. Every role can run this way, so the planner, review, drafts, chat and release notes can go on Cursor as well as the implementer. Slice 3 tests the implementer's resume, its limit and the time guard end to end.
- Asks' button presses (agent.md section 6.6) come back in the same result as today, so Ask Claude on Cursor can press the same buttons through the same checks.
- Tested in `cursor.test.ts` with recorded `stream-json` outputs: a good block; a block followed by text; no block then a good one on the retry; a block failing the schema three times; text with two blocks (the last wins).

**Claude Code's own structured output** needs none of this: `--json-schema` makes the model call a `StructuredOutput` tool, and Claude Code checks and retries that call itself (up to 5 times) without our code seeing the attempts. The one failure of that mechanism that reaches `spawnWithRetries`: a long field (a long `changeBody`, say) makes the model's reply run out of its own turn before the call's JSON closes, every one of those 5 retries fails the same way, and the session ends `error_max_structured_output_retries`. `spawnWithRetries` treats that the same as Cursor's "no valid result": one resume, with an instruction to drastically shorten any long text field (`claudeRetry` in `claude.ts`), rather than Claude Code's own generic "retry with valid JSON", which doesn't make the model write less. Tested in `claude.test.ts` with a fake `claude` binary.
