# 9.3.1 Ideas, in this Rust agent

Status: v0.2, 2026-11-11, backlog item `remove-ideas-round`, replaces the queue and daily round described in the first version of this file

Theme: Orchestration

Kind: change

The behaviour is the "Ideas" bullet of [9.3](09.3-what-the-computer-does-when-a-command-asks.md). This Rust agent no longer generates ideas: the TypeScript agent dropped its ideas round (Retaskable.com #3275, #3310, #3327, #3329, #3335), and this file now describes only what is left of ideas here, Build this.

## Decisions

- **[Decided]** The agent keeps no ideas file and runs no daily ideas round. Nothing reads or writes `ideas.json`, and the agent never offers the store a round of ideas.
- **[Decided]** What stays is accepting an idea the store already holds (`idea_accept`, below), and the store's own idea queue is the store's.
- **[Proposal]** The `ideas-session` release flag goes with the round, and `idea_accept` no longer sits behind it. Accepting stays available to the site whenever the project is in `claim` mode.
- **[Proposal]** The daily vet pass (`driver/vet_daily.rs`) goes too, since it is a daily job wired the same way and judged against the ideas queue; the vet judging module and the hub's two suggestion ops are left in place, unused, until a later item decides their fate (section 6.7).

## Removed

Delete `src/ideas/` except `accept.rs` (its `model`, `profiles`, `store` queue reads and writes, `write`, `context` and `test_support` go, keeping only the types and store calls `accept` needs), `src/orchestrator/driver/ideas_round.rs` and its tests, `ideas_daily.rs` and `vet_daily.rs` (with `Machine::ideas_rounds` and `Machine::vet_rounds`), `prompts/ideas.md`, the `ideas_generate` command and its `ItemCommand::Ideas`, the `ideas` lock, the `_ideas` writer session and its `ideas` transcript role, and the `ideas-session` flag. `ideas_generate` from the site is nacked like any command this agent doesn't take.

## Build this (`idea_accept { idea }`)

`idea_accept { idea }` (a blank id, or any mode but `claim`, nacks). `commands::run` queues it (`view::IdeaCommand`) and answers nothing yet (`commands::PENDING`); the loop's `idea_pass` (`driver/idea_accept.rs`) runs `ideas::accept` for each queued one and sends its `ack`/`nack` up the project's open connection (`ItemCommands::answer`), which the connector audits then. `accept` reads `ideas_list` first: an id not there nacks "That idea isn't there any more.", one not waiting "That idea was already answered by @<login>." (no "by" when unknown), and an unreachable store "Couldn't answer the idea in the shared backlog: …" (the store's own `not_found`/`conflict` message when it refused). A Claude idea is queued with `draft_queue` as `<title>. <why>` plus ` (It builds on the feature "<feature>".)` when it has one, with `audience` set when it names exactly one user type, `requestedBy`/`assignee`/`startedBy` the presser; a person's idea (`addedBy` set) uses `personRequest`'s quoted text and its title, `requestedBy`/`assignee` its author, `startedBy` the presser and the note "From @<author>'s idea, Build this by @<presser>". Then `idea_answer { id, answer: "accept", draftId, for: { via: "command", login } }`; if only that fails, the draft stays, the failure is logged and the command is acked. `idea_later` and `idea_never` are the site's, nacked here like a project-wide `pause`.

## Acceptance

- No source file, test or prompt names `ideas.json`, `ideas_round`, `ideas_generate` or `prompts/ideas.md`; `src/ideas/` holds only `accept.rs` and what it needs to compile.
- Each minute's pass starts no ideas or vet session, whatever the flags or the store's `jobs_due`.
- `idea_accept` still acks and nacks with the same wording as above, tested with a fake store; `ideas_generate` is nacked as unknown.
- `cargo fmt`, `cargo clippy --all-targets -- -D warnings` and `cargo test` pass.
