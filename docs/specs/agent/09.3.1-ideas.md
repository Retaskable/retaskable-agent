# 9.3.1 Ideas, in this Rust agent

The behaviour is the "Ideas" bullet of [9.3](09.3-what-the-computer-does-when-a-command-asks.md); this file is how `src/ideas/` builds it.

- **The queue.** `src/ideas/` ports `agent/src/ideas.ts` and the shared backlog's own copy of the queue, `shared/storeIdeas.ts`, split by responsibility like `src/release_notes/`: `model` is the plain data types and the refill fold, `profiles` is the user types and the prompt builder, `store` reads and writes the shared backlog, `write` runs the session and picks the round, `accept` writes an idea up as a draft (below), and `test_support` holds this module's own shared fixtures. `Idea` and `IdeaSuggestion`/`IdeasResult` (`model`) are the queue's own idea and the session's raw answer (`IDEAS_RESULT_SCHEMA`, `agent/src/schemas.ts`), checked against `shared/storeIdeas.ts`'s `IDEA_LIMITS` (`IDEA_TITLE_MAX`, `IDEA_EXPERIENCE_MAX`, `IDEA_WHY_MAX`, `IDEA_WHY_NOW_MAX`, `IDEA_FOR_MAX`, `IDEA_FEATURE_MAX`, `IDEA_NEW_FEATURE_MAX`); `ideas_result_schema()` is `IDEAS_RESULT_SCHEMA`. `refilled(was, res, profiles, stamp, queue, max_waited)` ports `refilled` exactly: the `Queue` already waiting gets one more refill each (dropped once it's sat through `max_waited`, `ideasMaxWaits`'s default `IDEAS_MAX_WAITS_DEFAULT`), then the session's fresh ideas fill the rest up to `queue` (`ideasQueue`'s default `QUEUE`), skipping a blank title and one already waiting, accepted, or turned down Never, each keeping only the known user types up to `IDEA_FOR_MAX`, once each. `Profile` and `build_prompt` (`profiles`) are trimmed from `shared/audiences.ts`'s `Audience` to the fields the prompt shows; `build_prompt` fills `prompts/ideas.md` (ported byte for byte) with this project's words (`crate::prompt::project_words`), the repo, what prompted the round, how much room is left, the user types and an already-built `context` JSON value, through the same `crate::prompt::render_prompt` the release-notes prompt uses; `starter_profiles()` is a fixed, starter set of eight (`starterAudiences`, shared/audiences.ts) used when the store has no audiences. `context` (`context.rs`) builds the rest from the store: `round_context(live, ideas)` is `{ live, accepted, later, never, waiting, people }` (live at most 12, newest first; `waiting` Claude's ideas, `people` those with `addedBy`), `gather_live` reads `live` (done items ordered newest first by their PR's `mergedAt` from `gh pr list --state merged --base <baseBranch> --json url,mergedAt`, an item with no matching PR last), and `profiles_for(audiences)` turns the store's audiences (`facts_get { kind: "audiences" }`) into `Profile`s, falling back to `starter_profiles()`. `Ideas` (`store`) wraps `backlog::Client::op` for `ideas_list`, `ideas_round { ideas, after? }` and `idea_answer { id, answer, draftId? }` (backlog/06.2-operations.md), always sending `for: { via: "command", login? }` since every answer this agent carries out is a person's command; `queue_from_store` folds the store's own rows (`StoreIdeas`, trimmed from `shared/storeIdeas.ts`'s `IdeaList`) into a `Queue`, leaving a person's own waiting ideas (`addedBy` set) out of it, since a round must leave those alone (backlog/06.2-operations.md). `Writer`, `session_spec` and `run_round` (`write`) are the session half (`generate`/`write`, agent/src/ideas.ts): the read-only, ephemeral `writer` session on `budget.scout_usd`, asking for however much room is left in the queue (at least one), run through the caller's `run_session`, its answer folded in with `refilled` when it answers `ok`. A session that fails, won't start, or answers anything else leaves the queue waiting as it was, with "Claude hit its $… budget …" (or "couldn't think of ideas: …") as `Round::error`, the session's model and cost kept either way. `orchestrator::driver::ideas_round` runs one round (`run_round`) under the `IDEAS_LOCK` lock, so two computers don't think at once, reading the store and sending `ideas_round`. The daily chore is wired: each minute `Machine::ideas_rounds` (`driver/ideas_daily.rs`), for a live or `runs`-mode project that isn't paused and ticked, with the `ideas-session` release flag On and no round already running, asks the store (`DueAsker`, job `ideas`) whether a round is due and, for a day this computer hasn't tried yet, runs one under the `ideas` lock with `fresh` and `quiet`; the store decides the day from its last `ideas_round`, so no local copy is kept. Nothing calls the context builders but tests yet.
- **Build this (`idea_accept { idea }`) in this Rust agent**, behind the `ideas-session` flag (Off nacks it as a command this agent doesn't take; a blank id, or any mode but `claim`, nacks too). `commands::run` queues it (`view::IdeaCommand`) and answers nothing yet (`commands::PENDING`); the loop's `idea_pass` (`driver/idea_accept.rs`) records the flag each pass, runs `ideas::accept` for each queued one and sends its `ack`/`nack` up the project's open connection (`ItemCommands::answer`), which the connector audits then. `accept` reads `ideas_list` first: an id not there nacks "That idea isn't there any more.", one not waiting "That idea was already answered by @<login>." (no "by" when unknown), and an unreachable store "Couldn't answer the idea in the shared backlog: …" (the store's own `not_found`/`conflict` message when it refused). A Claude idea is queued with `draft_queue` as `<title>. <why>` plus ` (It builds on the feature "<feature>".)` when it has one, with `audience` set when it names exactly one user type, `requestedBy`/`assignee`/`startedBy` the presser; a person's idea (`addedBy` set) uses `personRequest`'s quoted text and its title, `requestedBy`/`assignee` its author, `startedBy` the presser and the note "From @<author>'s idea, Build this by @<presser>". Then `idea_answer { id, answer: "accept", draftId, for: { via: "command", login } }`; if only that fails, the draft stays, the failure is logged and the command is acked. `idea_later` and `idea_never` are the site's, nacked here like a project-wide `pause`.
- **The daily round and `ideas_generate`.** The daily chore is wired: each minute `Machine::ideas_rounds` (`driver/ideas_daily.rs`), for a live or `runs`-mode project that isn't paused and ticked, with the `ideas-session` release flag On and no round already running, asks the store (`DueAsker`, job `ideas`) whether a round is due and, for a day this computer hasn't tried yet, runs one under the `ideas` lock with `fresh` and `quiet`; the store decides the day from its last `ideas_round`, so no local copy is kept. A person's `ideas_generate { fresh? }` (`src/commands.rs`) is nacked before setup is finished ("Finish setup first.") or with the project paused ("The project is paused: resume it first."); otherwise it is acked and queued as `ItemCommand::Ideas { fresh }`. On its next pass the loop (`driver/item_commands.rs`, `ProjectLoop::ideas_command` in `driver/ideas_round.rs`) drops it, logged, when the `ideas-session` flag is Off; logs "Claude is already thinking of ideas." and starts nothing when this project's round is already running; and otherwise starts one non-quiet round as its own task (`fresh` empties the waiting queue first), reading the store's audiences and what went live (`gather_live`, falling back to the store's done titles when `gh` fails), and logs the round's outcome.
