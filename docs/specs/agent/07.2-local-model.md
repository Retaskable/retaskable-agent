### 7.2 Local model

Optionally, a local server that speaks the Anthropic Messages API (`<baseUrl>/v1/messages`), such as llama.cpp, adds capacity that doesn't use the subscription:

- **Extra capacity, at any usage level.** Review scouts and chore implementers (not a playtest fix) take the local slot whenever it's free, beside the Anthropic sessions, and otherwise run on their tier. Each asks when it's granted a slot, so the first to ask gets it and the rest don't wait for it. Both suit a small context: a scout reads only its share of the diff, and a chore is small. Roadmap implementers, the planner, the final reviewer and drafts don't, above the limit.
- **Fallback.** Near the limit implementers and scouts run on it, and every session does at the limit instead of waiting (the tier table in section 7.1). The first target is Tiel-Coder-35B served by llama.cpp at `http://localhost:11436` as `tiel-coder-35b`.

Retaskable still runs `claude -p` with the same arguments; only a local session's environment changes. There's no SDK, proxy or second runner. Config (section 10):

```json
"local": { "enabled": false, "baseUrl": "http://localhost:11436", "model": "" }
```

Missing means off. The computer's settings take it as a toggle plus the URL and model name, and refuse a URL that isn't `http(s)://` or an empty model name when it's on. Changing it applies in place like any settings change (section 7).

- **Is it up?** While it's on, the orchestrator checks `GET <baseUrl>/v1/models` every minute (plain HTTP, 5-second timeout). While that fails, the tiers act as if the fallback were off, and the snapshot says "local down".
- **Environment.** A local session gets, on top of Retaskable's own environment: `ANTHROPIC_BASE_URL=<baseUrl>`, `ANTHROPIC_AUTH_TOKEN=local`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, and `<model>` in `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL`, `ANTHROPIC_DEFAULT_HAIKU_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL` and `CLAUDE_CODE_SUBAGENT_MODEL`. It's started with `--model sonnet`, which that environment maps onto the local model. Other sessions get none of it, and a local session doesn't get theirs (section 6.2) but `ENABLE_CLAUDEAI_MCP_SERVERS=false`.
- **Permissions don't change.** Local sessions run with `--permission-mode auto`, never `--dangerously-skip-permissions` or `bypassPermissions`. Auto mode works against the local server; its classifier requests go there too, so the local model judges its own actions.
- **One local session at a time.** The server has a single slot (llama.cpp `-np 1`), so the `local` tier is capped at 1 and even priority items and asks wait for it. Local sessions don't count toward `concurrency`, and auto concurrency (section 7.1) ignores them when it judges whether work is waiting, since they don't use the subscription; Anthropic sessions keep running beside one.
- **No dollar caps.** `--max-budget-usd` isn't passed to local sessions. Claude Code still reports a `total_cost_usd` priced at Anthropic's rates; it's recorded as 0, so local sessions add nothing to today's spend.
- **No usage limit.** A local session reports no usage, and one that ends with a 429 isn't treated as a limit hit.
- **Context.** The first server has a 32k context window, so a long implementer session may not fit. Sessions that ran on Anthropic are never resumed locally (section 7.1).
- **In this Rust agent**, the session-level half of this section is ported: `src/local_model.rs`'s `check_up`/`watch` poll `GET <baseUrl>/v1/models` every minute, logging only on an up/down transition ("Is it up?"), and `watch` writes the result to the shared `LocalModel` handle, built once per computer in `main.rs` and passed down to the per-project jobs (the implementer, run, plan, look, draft and ask starters): `available()` is true only when local is on and the last check found it up (down until the first check answers), `target()` gives the `LocalTarget`, and the model's one slot ("One local session at a time") is taken with `try_take()`, which gives `None` at once when busy, or the async `take()`, which waits; a guard frees the slot on drop, a panic included. `down()` is true when local is on, a check has answered and the last one failed, and the `local-tier-ladder` flag is On (read from the shared flags client), and `view.rs`'s `snapshot` reports it as `usage.localDown: true`, absent otherwise ("Is it up?"). `watch` signals `subscribe_down()` whenever `down()` changes, and the connector sends a new snapshot on it, so the report follows the model rather than waiting for another change. `LocalModel::run()` waits for the slot and gives a `LocalRun` (the `LocalTarget` plus the slot, freed when it's dropped) and `try_run()` gives one only if the model is available and the slot is free right now. `src/config/machine.rs`'s `LocalModelConfig` and `local_model()` read the `local` config block and its `RETASKABLE_LOCAL_MODEL`/`RETASKABLE_LOCAL_URL` overrides, refusing an empty model name or a URL that isn't `http(s)://` with no userinfo (`valid_model_name`/`valid_local_url`); and `src/engines/claude.rs`'s `local_target`/`build_args`/`session_env` give a local session exactly the environment this section lists (`ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN=local`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, the model env vars, `--model sonnet`, no `--max-budget-usd`), with `SessionReader`'s `local` flag pricing it at 0 and never reading a 429 or a sign-in error off it (`src/engines/engine.rs`). `main.rs` spawns the watch once per computer when `local.enabled`. There is no settings page yet, so the file's own `local` block (not yet validated on load, only on the two environment variables above) is the only way to turn it on today, same as the rest of agent-settings.md. Behind the `local-tier-ladder` flag (`src/tiers.rs`'s `local_ladder_on`; Off keeps today's behaviour), a Claude implementer session uses the model: `src/orchestrator/session.rs`'s `attempt` passes `local_available` (the handle's `available()`) to `implementer_tier`, and when the tier is `local` waits for the slot with `run()`, holds it for the whole session and starts it with the `LocalTarget` and model `local` (which `claude.rs` starts as `--model sonnet` with the local environment), listed in the snapshot as `local`; `src/orchestrator/trial_host.rs` does the same for the trial. In `src/runs/chore.rs`, `tier_for` gives a chore other than a playtest fix `try_run()`: it runs locally with the slot, or on `chore_tier()` at once when the model is down or the slot busy, and a playtest fix and a roadmap piece take the slot only by the implementer's tier rows (a piece's tier is read with no usage reading, so only an engine set to `local` takes it above those rows). An engine set to `local` (`engines/place.rs`'s `Placement::local`; for the implementer's start, `ClaudeStarter` reads the role's engine from the engine choice) takes the model while it's available — a chore too, which then waits for a busy slot — and otherwise the role's tier. A session on Cursor, pi or Codex never takes the slot, and its `local` tier reads as `sonnet` ([03-choosing-the-engine.md](../engines/03-choosing-the-engine.md) section 3.2). Review scouts and the final reviewer use it too (`src/orchestrator/piece_review.rs`'s `review_models`): with the flag On, a Claude scout that isn't already on `local` takes the free slot with `try_take()` and runs as `local` (the `LocalTarget`, model `local`), otherwise it runs on `scout_tier`, and when that comes out `local` it waits for the slot with `take()`; the final reviewer runs on `top_tier`, so it is local only below `pauseBelowPct`; a Cursor, pi or Codex scout never takes the slot; the role comes from `review_lane`, not from the model. Off, scouts run on `sonnet` and the reviewer on `opus`. Other roles are covered in section 7.1, and a resumed session (a gate round's fix, a restart's resume) stays on the backend it started on: `attempt` reads the model on the first line of the session's own transcript (`engines/transcripts.rs`'s `started_on`, the run folder's `<sessionId>.jsonl`). A `local` one goes back to the model, waiting for the slot, while it's available; otherwise it resumes on its Anthropic tier. Any other model, or a transcript that's missing or can't be read, counts as Anthropic and never takes the model, so it goes on `sonnet`. The wait-for-reset row collapses to `sonnet` until a waiting state exists, the same as `engineFor` in [03-choosing-the-engine.md](../engines/03-choosing-the-engine.md).
