### 6.10 Spec layout

(2026-10-22) A session reads specs a section at a time, so no spec file is bigger than a session needs: every file under `docs/specs/` is at most 40,000 characters (the spec size gate, section 6.2).

- **A split spec.** A spec over the limit is an index plus a folder: `docs/specs/<name>.md` keeps its opening (the title and metadata before the first `##`), then a line saying it's split, then each `##` heading followed by links to that section's files. Each `##` section is its own file in `docs/specs/<name>/`, moved as is: `NN-<slug>.md` (`06-sessions.md`). A section still over the limit splits at its `###` headings, each its own file `NN.M-<slug>.md` (`06.2-implementer.md`), with the text before the first `###` left in `NN-<slug>.md`. A piece still over the limit splits at the paragraph break nearest 35,000 characters into `NN-<slug>-2.md`, listed in the index as "(continued)".
- **References still resolve.** "`<name>.md` section 7" names the index, whose `## 7.` lists the files that hold it. Links in moved text gain `../`, and links to an anchor in the same spec point at the section file that now holds it.
- **Reading one.** `shared/specParts.ts` reads the layout: `specParts` lists an index's section files in order, `wholeSpec` joins them back into the whole text (the start report's spec code, `agent/src/startFiles.ts`), and `sectionFile` finds the file holding a section number (release notes' spec links, `agent/src/releaseNotes.ts`). A hosted backlog reads only the top-level specs as items' specs (`specsAt`), so section files never become items. The MCP `read_spec` tool reads the index or any section file by path ([mcp.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/mcp.md)).
- **Splitting one.** `node --import tsx scripts/splitSpec.ts docs/specs/<name>.md` splits a spec this way and refuses to leave any file over the limit; a spec that's already split is skipped. The spec drafter splits a spec it grows past the limit the same way (`prompts/drafter.md`), and the spec scout reads the index, then only the sections it needs.


**In this Rust agent (as built).** The three halves of the layout are ported; the paths below are the code's.

- **Reading** (`src/spec_parts.rs`). `spec_parts(index, root)` reads the index: the text before its first `## ` line is the opening; from there on every `](path.md)` or `](path.md#anchor)` link is a candidate, kept only when the file sits directly in the spec's own folder (`<name>/`, beside the index) and only the first time it appears. A link anywhere else (another spec, a URL, a file in a sub-folder) is not a part. An index with no such link is an unsplit spec: `spec_parts` gives just the index itself, `whole_spec` its file's text and `section_file` the index for any number. `whole_spec` is the opening, then each part's text in index order, a newline added only where a part does not end in one. A file that can't be read counts as empty text, never an error. `section_file("6.2")` looks for the part whose name starts with those numbers (`06.2-…`); if none, it drops the last number and tries `6` (so a `###` that was not split out is found in its `##` file); `None` for a number no part holds or one that isn't dotted digits. A `-2` "(continued)" file keeps its section's number, so `section_file` finds the first piece of it.
- **Who uses it.** `src/implementer/start_files.rs` reads each spec an item links through `whole_spec` and `spec_parts`, so the code a split spec names is found in its section files and resolved from the first part's folder; `src/implementer/code_gates.rs` is the spec size gate (below). Nothing else in the agent reads a spec by section.
- **The gate** (`code_gates.rs`, section 6.2's *Spec size*). A file is a spec when its path matches `specs/<file>.md` or `specs/<folder>/<file>.md` (any case) and isn't under `node_modules`, `vendor`, `dist` or `build`. Only the files the change adds or edits are measured, by `spec_chars`: characters, not bytes, with `\r\n` counted as one. A limit of 0 turns the gate off. For each file over the limit it lists the file, its size and up to 3 headings to split at: the `##` headings (outside code fences, and not on line 1), else the `###` ones when there are none; it aims for `ceil(size / (0.8 × limit))` equal parts and picks the heading nearest each equal share, never the same line twice. The note to the session then repeats the folder layout above.
- **Splitting** (`src/spec_split.rs`, run as `retaskable split-spec -- docs/specs/<name>.md [--max 40000]`; exit 0 for split, already split or small enough, 1 when it refuses, 2 for bad arguments). A spec already read as split, or within the limit, is left alone and the command says so. Otherwise it cuts at `## ` lines outside code fences and names each file `NN-<slug>.md`: `NN` is the number the heading starts with when every heading has one and none repeats, else its place in the list (from 1); the slug is the heading's ASCII words lowercased, digit-only words dropped, joined by `-` and cut to 40 characters (`section` if none are left). A section over the limit is cut again at its `### ` lines into `NN.M-<slug>.md`, the text before the first one staying in `NN-<slug>.md`. Any piece still over the limit is cut at the paragraph break (a blank line) nearest 7/8 of the limit, 35,000 of 40,000, until each fits, into `-2`, `-3`… files listed as "(continued)". A piece with no paragraph break to cut at, or a spec with no `##` heading, makes it refuse. The index is the opening, a line saying it is split, then each original `##` heading and a link bullet per file (the `###` title after the link; "(continued)" for a `-N` file). Links in moved text are rewritten to still resolve (same-spec anchors point at the file now holding the heading, relative links gain `../`), leaving code fences and inline code alone. It writes nothing unless every file, the index included, fits.
- **[Proposal] Gaps to close.** None of these changes what a person sees; they make the layout safer for the sessions that write it.
  - **A spec the gate cannot fix.** A change that edits a split spec's index so it grows past the limit (many long `Items:` or status lines) gets a note telling it to split the index, which it can't: say instead that the opening itself is too long and to shorten it. Likewise a section file with a single paragraph over the limit gets "shorten it or move part of it to its own spec", not a split suggestion.
  - **Re-splitting.** A split spec whose section file grows past the limit is not "already split" work for `split-spec` (it skips any spec it reads as split). Let `retaskable split-spec` accept a section file's path and split that one file at its `###` headings and paragraph breaks, adding its new files to the index in place and leaving every other file untouched.
  - **Index drift.** After a change, the gate checks that every file in a touched spec's folder is linked from its index and every link resolves, and refuses with the missing or dangling names, so a file added by hand can't be read as nothing by `spec_parts`.
- **[Proposal] Tests (existing and to add).** `src/spec_parts.rs` and `src/spec_split.rs` test an unsplit spec being itself, index order with continued files, `whole_spec`, `section_file` and its fallback, `###` and paragraph splitting at 7/8, fenced headings, the refusal that writes nothing, link and anchor rewriting. To add: a link to a file outside the folder is no part; an unreadable part reads as empty; a `section_file` for `6.2.1`; a `-2` file found by its number; the gate on a spec exactly at the limit (not over) and on one with `\r\n` endings; a section file path given to `split-spec`; a stray file in the folder refused as drift.
- **[Proposal] Acceptance.** The Rust agent splits `agent.md`-sized text and `spec_parts` reads it back to the same whole text; a change that leaves a spec at exactly 40,000 characters passes the gate and one at 40,001 is refused with at most 3 split points; a split spec's index over the limit is told to shorten its opening; an unlinked file in a spec's folder is named by the gate.
