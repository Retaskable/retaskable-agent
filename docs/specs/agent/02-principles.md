## 2. Principles

- **As simple as possible.** Everything is Claude Code CLI (`claude -p`), `git` and the code host's CLI (`gh` or `glab`), driven by one small process. No Agent SDK, no database, no queue. A second engine, Cursor's CLI agent (`cursor-agent -p`), is chosen per computer and per role, beside Claude Code and not replacing it ([engines.md](../engines.md)); everything below about `claude -p` is the Claude Code engine.
- **The orchestrator is deterministic.** Claude does the coding and the reviewing, always through the structured result schemas below. The orchestrator's code handles worktrees, CI polling, merging and state transitions, never an LLM.
- **The store is the source of truth.** The agent never keeps its own copy of what's done or what's next. It asks the shared backlog store ([backlog.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/backlog.md)) for work and reports back to it. When the store can't be reached it stops and waits: it fails closed, and never falls back to a local list.
- **The server never sees or touches the user's code.** The computer sends the store and the hub only derived results (states, titles, summaries a session wrote, raw check results), never source or diffs, and transcripts are streamed live and never stored. Approved specs are committed to the user's repo, and spec content never goes to the store.
- **Models follow the usage limit.** The final reviewer runs on Opus, the best model available. Implementers start on Sonnet and move to Opus for a retry, a reopened item or a big one; the drafter, the triager and review scouts run on Sonnet; each steps down as the 5-hour usage limit runs out (section 7.1). With the local model on (section 7.2), scouts and chores also use its slot whenever it's free, it takes over implementers and scouts near the limit, and everything at the limit instead of waiting. Haiku runs only the read-only writing (release notes, ideas, vetting suggestions), since Claude Code won't run it in auto mode.
- **Opus judges, it doesn't read every line.** Review goes cheapest first: deterministic checks, then cheap scout sessions that each look for one kind of issue, then one Opus pass over their findings (section 6.3). The choice is a threshold lookup in code, not an LLM decision.
- **Permissions:** every Claude Code session runs with `--permission-mode auto`. The orchestrator **never** uses `--dangerously-skip-permissions` or `bypassPermissions`. Every Cursor session runs under the project's allowlist written as the lane's `.cursor/cli.json`, **never** with `--force` ([engines.md](../engines.md) section 6).
- **It fails safe.** Anything stuck, over budget or ambiguous goes to `needs_human` and is skipped, not retried forever.
