## 4. Every agent on the shared backlog (shared-backlog-auto-link)

Until this item a machine linked to the backlog store by hand: the tray's **Shared backlog ▸ Link to the shared backlog** started the store's device flow and opened its `/link?code=…` page, and **Forget the shared backlog** deleted the link (tray.md section 4.6, `agent/src/backlogLink.ts`). Every project already runs on the store ([backlog.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/backlog.md) section 15, "Shared is the only choice"), so a machine that isn't linked can claim nothing and fails closed: the manual step only ever gets in the way.

- **It's part of installing.** The first run's steps are: link this computer to retaskable.com, then approve the shared backlog. The agent opens the second page itself the moment the first is approved, so the user sees one page after another and clicks once on each, never a menu. Since setup-window a release build starts the first link by itself too, and opens Getting started after the second ([setup-in-app.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/setup-in-app.md) section 3.0).
- **The agent links itself.** At start, and right after a retaskable.com link is approved, an agent with no store link starts the store's device flow on its own and opens the `/link` page, exactly as the tray's item does today. One page, opened for them, with one GitHub click once the store's GitHub App is authorised.
- **While it waits**, it's a request like any other: the tray's **Requests** shows "Approve the shared backlog" with **Open the link page**, the desktop notification says so, and the tooltip counts it in "N waiting for you".
- **The tray loses Shared backlog**: the submenu and `forget_backlog` (`agent/src/tray.ts`, `agent/src/trayAgent.ts`) go, and the terminal menu's with them. `link_backlog` stays as the request's **Link again**.
- **Unlinking** happens only on the store's agents page. An agent unlinked there doesn't link itself again until it restarts or the user chooses **Link again** from the request it shows ("Unlinked on backlog.retaskable.com: link again?"), so unlinking on the site is respected.
- **A failed or expired code** is started again the next time the agent starts, never in a loop.
- **`npm run link -- backlog`** stays, for checkouts and containers (docker.md).
  - **Linking by itself**: `BacklogLink.autoLink()` (`agent/src/backlogLink.ts`) starts the store's device flow only when `backlog.url` is good, this machine holds no store link, no code is waiting and the store hasn't answered `invalid_grant` since the agent started (`BacklogStore.unlinkedOnSite()`, kept in memory, so a restart links again). `agent/src/index.ts` calls it once at start, when the agent already holds a retaskable.com link (before that, retaskable.com's link comes first), and from the retaskable.com `Linker`'s `onLinked`, so the second page opens the moment the first is approved. With a code it prints "Approve the shared backlog: <url>", opens the store's `/link?code=…` in the default browser (`openUrl`) and shows the notification "Retaskable: approve the shared backlog" (the terminal menu's highlighted line instead); a failed or expired code is logged and waits for the next start. Linked, each hosted project's socket reconnects at once, as before.
  - **The request** (`agent/src/tray.ts`, `request.backlog`, one fixed item after the 10 request slots, hidden while there's none): counted in **Requests (N)** and the tooltip's "N waiting for you"; **Approve the shared backlog (<code>)** with **Open the link page** while a code waits, **Unlinked on <store host>: link again?** with **Link again** (`link_backlog`), or, once a retaskable.com link is held and nothing waits (the code failed or expired), **Link to the shared backlog** with the failure and **Link**. None while linked, while `backlog.url` is bad, or while no retaskable.com link is held and nothing waits. The icon stays retaskable.com's. The terminal menu highlights it as a request.
  - **Gone**: the tray's **Shared backlog ▸** submenu, `forget_backlog`, `BacklogLink.forget()` and `BacklogStore.forget()`: a machine's store link is removed only on the store's agents page. The board's **Link again** (the `backlog_link` command) stays.
  - **In this Rust agent**, `backlog::auto_link` (`src/backlog.rs`) is `BacklogLink.autoLink()`: it starts the device flow only when `backlog::url` (`RETASKABLE_BACKLOG_URL`, else the default) is a good address and this machine's keychain holds no token for it yet, never on a timer. `main.rs` calls it once at start when a retaskable.com link is already held, and once right after `retaskable link [cloud]` approves one in the terminal, opening the store's `/link?code=…` page itself (`link::open_url`, no shell) the moment the code is ready — the second page opening as soon as the first is approved, the same as `onLinked` above. `retaskable link backlog` is this crate's `npm run link -- backlog`. Neither path retries within a run, so a failed or expired code waits for the next start or that command. There's no in-memory `unlinkedOnSite` flag yet, since nothing in this crate calls the store with the backlog's own token to ever see an `invalid_grant` back: `backlog::Client::list` takes a token already, but picking a tier and actually calling it is the pool/orchestrator's job (milestones 3 and 4 of [11-build-milestones.md](../agent/11-build-milestones.md)), which doesn't exist in this crate yet — a later piece, not a further slice of this item. The request this section describes (**Requests**, its notification, the terminal menu's highlight) has the same gap one level up: there's no tray or terminal menu in this crate yet either ([tray/04-the-tray-agent.md](../tray/04-the-tray-agent.md) sections 4.2 and 4.6–4.7), so today a waiting or failed code is only logged and printed, never shown to the person at the machine beyond the terminal's own `retaskable link backlog` output.

### 4.1 Why one approval is still needed

The store has its own GitHub sign-in so that no retaskable.com environment vouches for an agent in a store the others use ([backlog.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/backlog.md) section 4.1, decision (b)). Linking with no approval at all would mean the store trusting retaskable.com's link, reversing that decision. **[Decided]** (2026-10-18, the human: "one click as part of the install process is fine") Keep the one approval and open it for the user as an install step, as above; [backlog.md](https://github.com/Retaskable/Retaskable.com/blob/main/docs/specs/backlog.md) section 4.1 doesn't change.
